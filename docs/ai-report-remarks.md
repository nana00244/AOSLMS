# AI teacher remarks

On Report cards, select a pupil and term, choose **Generate AI teacher remark**, then **Generate draft**. Review/edit the result and choose **Save teacher remark**. Cancel leaves the saved remark untouched. Saving uses the same durable Supabase-backed queue as other report edits and clears report verification so the changed report can be reviewed again. Pending score saves must finish before generation. Changed scores or a remotely changed remark require regeneration or reopening the dialog.

The `generate-report-remark` Edge Function validates the authenticated, active staff profile on every call. Administrators can select any report term; teachers can use only their assigned classes, subjects and the active term. Scores come from the private database document, never a client-supplied prompt. Missing grades are excluded, while recorded zero scores are retained. Only canonical subject names and numeric scores are sent to OpenAI; names, IDs, existing remarks and other student information are not included. A subject-restricted teacher's draft covers only their accessible subjects.

The function uses GPT-4.1 mini through the Responses API with `store: false`, a 30-second timeout, and a 250-token output cap. This disables response application storage; it is not a promise of zero provider retention. See [OpenAI data controls](https://developers.openai.com/api/docs/guides/your-data) and [Responses migration guide](https://developers.openai.com/api/docs/guides/migrate-to-responses). AI output can be inaccurate: teacher review is required, and no invented fallback comment is saved when generation fails.

Provision `OPENAI_API_KEY` using [Supabase Edge Function secrets](https://supabase.com/docs/guides/functions/secrets). Never use a `VITE_` variable or commit a key. For rotation, replace that secret in the Supabase dashboard; the frontend needs no key or rebuild. Set an appropriate OpenAI project spending limit too. Provider errors are sanitized; request bodies, credentials and generated remarks are not logged by this function.

Deploy the migration with `npx supabase db push --linked --yes`, then `npx supabase functions deploy generate-report-remark --project-ref YOUR_PROJECT`. Gateway JWT verification is disabled for compatibility with the project's publishable-key setup, but the function always validates the bearer token with Auth before reading any data or calling OpenAI.

Atomic database counters limit each staff member to 20 attempts/minute and 200/day, and the school to 1,000/day (UTC). Failed provider requests count too. The counter table has RLS and no client policies, and its RPC is executable only by `service_role`. No student scores or remarks are stored in the counters.

Verification: `npm test`, `npm run build`, and the isolated live browser test via `node scripts/verify-with-temporary-admin.mjs --ai-remarks`. Live verification uses fictional pupils, makes a real OpenAI request, verifies saving/reloading from Supabase, and removes its fixtures. If OpenAI rejects the real request with a quota/rate limit, the test explicitly reports that limitation and uses a labelled test response only for the browser review/save checks; that does not verify successful live generation. On 2026-10-13, the provider returned HTTP 429, while the review/save/reload and authorization checks passed. Check the OpenAI project's API billing and model rate limits before relying on generation.

The Supabase security advisor also reports the pre-existing disabled leaked-password protection setting. See [password protection](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection) for its plan requirements and configuration. Intentional service-only tables are reported as RLS enabled without client policies; they remain inaccessible to client roles.
